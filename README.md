# 智美成ERP系统 · 绿色版

一套**免安装、双击即用**的 PHP + MySQL 企业资源计划系统。所有运行时（PHP 8.3 / MySQL 8.0 / nginx）都已内置在项目目录内，**不写注册表、不注册 Windows 服务、不往系统目录里放任何文件**，解压即用。

支持**多人同时在线编辑**：nginx + 8 个 php-cgi 进程构成真正的多进程并发，配合乐观锁、行锁与编辑心跳，保证多人同时改单据时**不丢数据、不互相覆盖**。

> 📦 本仓库同时提供**加密版**（加壳 + 30 天试用 + 激活码授权）与**局域网客户端**，
> 详见 [第十四章](#十四加密版与局域网客户端) 与 `docs\加密版说明.md`。

## 一、启动与停止（3 个文件，全部双击即可）

| 文件 | 作用 |
| --- | --- |
| **启动系统.bat** | 一键启动。首次运行会自动初始化 MySQL 数据目录、建库建表、写入种子数据，然后拉起 nginx + 8×php-cgi，并自动打开浏览器 |
| **停止系统.bat** | 一键停止 MySQL / nginx / php-cgi 全部进程 |
| **初始化数据库.bat** | 重建数据库（**会清空全部业务数据**）。需要**输入 Y 确认 + 连输两次管理员密码**（两次必须一致、且与库里 admin 的密码相符），防止误触 |

启动后按任意键关闭黑色窗口即可，**服务会继续在后台运行**。

> 提示：所有 `.bat` 内部只写英文，避免 cmd 按系统 ANSI 代码页解析 UTF-8 中文导致命令被截断；中文提示由 PowerShell 层的 `bin\start.ps1` 输出。

### 核心业务口径（采购 / 生产 / 财务）

**① 物料需求清单（MRP）＝订单驱动 BOM 净需求**

```
客户订单(未交付) → 展开 BOM(逐层子件,含损耗率) → 毛需求
净需求 = 毛需求 − 现有库存 − 在途(已下单未到货 + 已请购未下单)
```

- **生产不良率**参与展开：要拿到 `Q` 个合格品，需投产 `Q ÷ (1 − 不良率)`，因此下层原料需求会自动放大。物料档案维护默认不良率，MRP 页面可按行手工改后「按不良率重算」。
- **采购数量可手工调整**：净需求是理论值，采购员可按不良率、最小起订量、供应商打包价在页面上直接改数量，**生成请购单时以手工值为准**，并在明细备注里留痕（`手工调整为 700(净需求 631.579)`）。
- 勾选缺料行 → **一键生成请购单(PR)**（草稿），再走「提交 → 审核 → 转采购订单」。有 BOM 的成品/半成品标「需生产」，走工单而不是请购。

**② 采购的两种付款条件**

| 付款条件 | 流程 | 系统动作 |
| --- | --- | --- |
| **预付款（款到发货）** | 先打款 → 后发货 → 发票随后寄到再补登 | 采购订单**审核时**按预付比例自动生成「预付款单」；财务在收付款单上核销它；**收货过账时该预付款单就地转为正式应付**（金额 = 价税合计、已付金额保留、尾款按账期到期） |
| **账期（货到付款）** | 先发货 → 再开票 → 按账期打款 | 收货过账生成应付，到期日 = 收货日 + 供应商账期，账款提醒提前预警 |

付款条件在**供应商档案**维护默认值，新建采购订单时自动带出，也可按单调整。

**③ 收货时发票还没到，怎么记账？（暂估 → 补登发票 → 差异调整）**

| 时点 | 库存成本 | 进项税 | 应付账款 |
| --- | --- | --- | --- |
| 收货过账、发票未到 | **暂估**：按普票口径，价税合计全额进成本 | 0 | 价税合计（不变） |
| 次月补登**普通发票** | 不变 | 0 | 不变 |
| 次月补登**增值税专用发票** | 由含税调整为**不含税**，库存单位成本同步回改 | 确认**可抵扣**进项税 | **不变**（往来款恒按价税合计） |

> 关键点：**往来款（应付/应收）恒按价税合计记账**，补票**不会**改变应付金额，只改变成本与进项税。原暂估发票台账自动作废并补写正式记录，库存流水留一条成本调整记录。

**④ 收付款核销**：收付款单增加「核销类型 / 核销单据」，**付款核销应付、回款核销应收**，核销后该笔自动从账款提醒里消失。核销有四道校验：方向必须匹配（收款只能核应收、付款只能核应付）、往来单位必须一致、单据必须未结清、**核销金额不得超过未结余额**。

**录入校验与安全（写库前统一把关）**：所有单据在保存前都会按表结构做一次完整校验——文本长度按**字符**计（一个汉字算 1 个字符，不是 1 个字节），超限时**明确拒绝**并提示「XX 长度不能超过 N 个字符（当前 M 个）」，**绝不静默截断**；金额、数量、工时必须是数字且不允许为负；数值超出列精度、日期非法同样被拦下并给出可读提示（HTTP 422，而不是「系统内部错误」）。所有 SQL 走 PDO 预处理，页面输出一律 HTML 转义，详见说明书 1.7 节。

### 核心业务口径（工资 · 个税 · 五险一金）

**⑤ 个人所得税：累计预扣预缴法**（居民个人工资薪金所得）

```
累计应纳税所得额 = 累计收入 − 累计减除费用 − 累计专项扣除 − 累计专项附加扣除
累计应纳税额     = 累计应纳税所得额 × 预扣率 − 速算扣除数
本月应预扣税额   = 累计应纳税额 − 累计已预扣税额
```

- **七级累进预扣率表**（法定，税率表见 `app\Core\IncomeTax::CUMULATIVE_TABLE`）：

  | 级数 | 累计预扣预缴应纳税所得额 | 预扣率 | 速算扣除数 |
  | --- | --- | --- | --- |
  | 1 | 不超过 36,000 | 3% | 0 |
  | 2 | 36,000 ~ 144,000 | 10% | 2,520 |
  | 3 | 144,000 ~ 300,000 | 20% | 16,920 |
  | 4 | 300,000 ~ 420,000 | 25% | 31,920 |
  | 5 | 420,000 ~ 660,000 | 30% | 52,920 |
  | 6 | 660,000 ~ 960,000 | 35% | 85,920 |
  | 7 | 超过 960,000 | 45% | 181,920 |

- **累计减除费用** = 每月减除费用（默认 5,000 元，系统参数 `tax.basic_deduction` 可改）× 累计计税月份数；
- **累计专项扣除** = 累计五险一金个人缴纳部分；
- **累计专项附加扣除** = 员工档案里逐人维护的七项：子女教育、3 岁以下婴幼儿照护、继续教育、大病医疗、住房贷款利息、住房租金、赡养老人（表单里带法定标准提示）；
- **累计口径的影响**：一年里的每个月个税金额**不相同**（前面月份扣得少、后面月份扣得多），全年总额与按月计算相同。所以**改了某个月的工资会影响本年后续月份的个税** —— 系统在保存工资时**自动级联重算**同年后续月份（已确认/已发放的不动），也可以用工资表页的「♻️ 按年重算工资」整年重算。

> 依据：国家税务总局公告 2018 年第 61 号、财税〔2018〕164 号、财税〔2023〕30 号。

**⑥ 五险一金：四个分项各算各的**

| 分项 | 缴费基数来源 | 个人比例来源 |
| --- | --- | --- |
| 基本养老保险 | 员工档案「养老缴费基数」>0 时用它，否则用**工资基数**（基本 + 岗位 + 绩效 + 津贴） | 档案比例 ≥0 时用它，否则用系统参数 `si.pension_rate`（默认 8%） |
| 基本医疗保险 | 同上 | `si.medical_rate`（默认 2%） |
| 失业保险 | 同上 | `si.unemployment_rate`（默认 0.5%） |
| 住房公积金 | 同上 | `si.housing_fund_rate`（默认 12%） |

- 缴费基数受系统参数 `si.base_min` / `si.base_max` 封顶（默认 0 = 不封顶，按当地社平工资的 60%~300% 设定）；
- 员工档案里比例填 **-1** 表示「按系统参数默认」，填 0 表示「不缴这一项」；
- 工资表上「社保公积金」列鼠标悬停可看四个分项的金额；导出 CSV 里有养老/医疗/失业/公积金四列。

## 五、导入（BOM 物料清单批量导入）

入口：**生产管理 → 物料清单 →「⬆ 导入」**（`GET /import/bom`），需 `production.bom.edit` 权限。

| 功能 | 说明 |
| --- | --- |
| **模板下载** | `GET /import/bom/template`，含表头 + 一行示例 + 填写说明 |
| **列名匹配** | **按表头名匹配列**，用户在 Excel 里调整列顺序也能正确导入；每列都支持多个别名（如「子件用量 / 单位用量 / 用量」） |
| **同一 BOM 多行** | 同一 BOM 编码的多行 = 多个子件；主档字段（名称/产出物料/版本/基准产出数量）只在第一行填，后续行留空即自动继承 |
| **覆盖式导入** | BOM 编码已存在 → 更新主档并**整体替换**子件明细（与手工编辑语义一致）；不存在 → 新建 |
| **逐行校验** | 编码为空 / 物料不存在 / 子件与产出物料相同 / 用量非正 / 损耗率非数字 / 基准数量非正 / 同 BOM 子件重复 —— **错误行跳过**，页面列出「行号 + 原因」，其余正常导入 |
| **事务写入** | 合法行在**单一事务**内落库，中途出错整体回滚，不留半截数据 |
| **公式注入防护** | 单元格内容以 `= + - @` 开头时自动加 `'` 前缀，Excel 打开不会当成公式执行 |

导入结果页同时给出：成功导入的 BOM 清单（新增/更新、子件数、来源行号）、被跳过的错误行明细，以及本次导入涉及的全部 BOM 列表。

## 六、部门级权限与数据隔离

系统的权限分**三层**，可分别配置：

| 层级 | 在哪配 | 管什么 |
| --- | --- | --- |
| **角色权限** | 系统管理 → 角色权限 → 分配权限 | 全局权限模板，一个角色一套 |
| **部门岗位** | 系统管理 → 部门岗位 | 每个部门的「员工 / 主管」单独一套 |
| **数据范围** | 角色表单 + 岗位表单 | 能看到哪些部门的数据 |

**权限矩阵（模块 × 动作）**：角色和岗位的权限页都是矩阵表，行是单据/资料，列是动作，**逐格勾选**：

| 动作 | 权限码 | 含义 |
| --- | --- | --- |
| 查看 | `purchase.order` | 能打开列表与详情 |
| 录入 | `purchase.order.edit` | 能新建、修改 |
| 提交 | `purchase.order.submit` | 能提交待审 |
| **审核** | `purchase.order.approve` | **能审核别人（或自己）录入的单据** |
| 过账 | `purchase.order.post` | 能执行入库/出库等过账动作 |
| 删除 / 作废 / 关闭 / 下达 | `.delete` / `.void` / `.close` / `.release` | 高风险动作单独授权 |

> **录入与审核天然分离** —— 审核是独立权限码，不勾就没有审核按钮。这解决了旧版「按模块前缀一把梭授权，导致普通员工也能审核/删除/作废订单」的问题（现已修复并有测试守护）。

**部门岗位**：每个部门可建「业务员工」「部门主管」等岗位，岗位绑定**权限集 + 数据范围**，本部门同类人员套用同一岗位，人员变动不用重配。

- 岗位权限与角色权限**取并集**（岗位只加不减）。
- 典型用法：采购部主管岗位额外授予 `purchase.order.approve`，采购部专员岗位只给查看权 —— 录单和审核就分开了。
- 用户在「用户管理 → 编辑」里选「部门岗位」即可生效。

**数据范围（真正生效的部门隔离）**：

| 范围 | 能看到的数据 |
| --- | --- |
| 全部数据 | 全公司（管理员、财务等） |
| **本部门及下级部门** | 本部门 + 所有下级部门（部门主管） |
| **本部门数据** | 仅本部门（业务员工） |
| 仅本人数据 | 仅自己创建的单据 |

范围取「角色范围」与「岗位范围」中**更严格**的一个。作用点覆盖：单据列表、单据详情（越权直接 403）、单据导出、库存/销售/采购/账龄/经营简表报表。所有单据在创建时自动写入归属部门。

**职责分离（可开关）**：系统参数 `sod.enabled` 默认开启 —— **录入人不能审核自己录入的单据**（按钮不显示、接口拦截）。超级管理员豁免；小团队需要自审自批时可在「系统参数」里关掉。

## 七、多人同时在线编辑（并发控制）

系统为「多人同时在线」做了四层保障：

1. **乐观锁（version）** —— 所有可编辑主表带 `version` 字段。保存时校验 `WHERE id = ? AND version = ?`，若他人已改过则返回 **HTTP 409**，并以「服务器当前值 → 你的值」的差异对比页重新渲染（**保留你已填的内容**），可选择「强制覆盖保存」或复制内容后刷新放弃。
2. **行锁（SELECT ... FOR UPDATE）** —— 写库时先对单据行加锁，避免两人同时提交产生丢失更新。
3. **原子扣减防超卖** —— 出库采用带条件的原子 UPDATE + 行锁，库存不足时整单回滚。实测 5 张单各出 30、库存仅 100 时：**成功 3 张，其余回滚，库存最终为 10，全库无负库存**。
4. **编辑占用提示** —— 打开单据即上报「正在编辑」心跳，右上角实时显示在线人数；他人正在编辑同单据时页面顶部给出黄色提示条。

**进程看门狗（绿色版稳定性）**：内置 `bin\watchdog.ps1`，每 5 秒检查一次 9000-9003 四个 FastCGI 端口的监听状态，某个 php-cgi 意外退出时**自动补拉**（实测 5 秒内恢复），避免全站 502。日志在 `runtime\logs\watchdog.log`；停止服务时看门狗会先退出，不会把刚停掉的进程再拉起来。

**上游自动重试（单进程崩溃不中断业务）**：nginx 的 FastCGI 池启用了 `max_fails=0` 与 `fastcgi_next_upstream error timeout invalid_header`，某个 php-cgi 进程在处理请求时意外退出，nginx 会**自动换一个进程重试**而不是直接返回 502；非幂等请求（POST）在上游已收到请求后不会被重放，因此不会重复提交单据。实测：手动结束一个 php-cgi 后，连续 12 次页面访问全部返回 200。

## 十一、常用运维

### 改端口

```powershell
# Web 端口 8091、数据库端口 3308、FastCGI 端口段 9020
powershell -NoProfile -ExecutionPolicy Bypass -File bin\start.ps1 -HttpPort 8091 -DbPort 3308 -CgiBasePort 9020
```

> FastCGI 端口段必须与另一套实例错开，否则 nginx 会把请求转发到别人的 php-cgi 上，
> 表现为「登录总是 419 / 会话莫名丢失」。启动脚本会先检查端口段是否被占用，被占用会直接报错退出。

### 换 php-cgi 进程数（并发能力）

默认 8 个；机器性能较弱可调小：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File bin\start.ps1 -CgiWorkers 4
```

### 数据备份与恢复

- **立即备份**：系统管理 → 数据备份 → 「立即备份」，SQL 文件输出到 `storage\backup\`（纯 PHP 生成，不依赖外部 mysqldump；备份/恢复全程走 PHP + PDO，**不调用 mysql 客户端**，所以中文安装目录也能用）。
- **定时备份**：同一页面可设置「启用定时备份 / 每天执行时间 / 备份保留天数」，页面会显示**下次执行时间**与**上次执行结果**。
  - 参数存在 `sys_config` 表（`backup.auto_enabled` / `backup.auto_time` / `backup.keep_days`），管理员随时改、立即生效；
  - 默认**启用**，每天 **02:30** 执行，备份文件保留 **7 天**（超期自动清理）；
  - 调度由系统内置的看门狗进程（`bin\watchdog.ps1`）**每分钟检查一次**，执行时间误差不超过 1 分钟，不用另起常驻进程；
  - 去重用的是独立键 `backup.auto_last_run`（只记「定时备份」），所以**手工点的「立即备份」不会「吃掉」当天的 02:30 计划点**；
  - 也可以命令行手动触发：`php database\backup.php --run`（立刻备份一次）、`--status`（查看当前设置）。
- **数据恢复**：同一页面每条备份都有「恢复」按钮，**只有管理员**（角色 `admin`，或持有 `system.restore` 权限）可以点。
  - 恢复要过三道关：管理员权限 → CSRF 令牌 → 页面弹窗里**再输入一次数据库名**确认；
  - 恢复前系统**自动为当前库生成一份安全备份**（万一恢复的是错的还能退回来）；
  - 恢复期间系统进入**维护模式**（其他页面一律返回 503），完成后自动解除；
  - 备份文件会先做**完整性校验**（必须有建表语句、必须有收尾标记、不能被截断），不合格直接拒绝执行 —— 绝不会在文件有问题时去动数据库；
  - 恢复是用备份文件**覆盖**当前数据库，操作不可撤销，请谨慎。
- **整体迁移**：整个 `E:\PHP_ERP` 目录拷到目标机器，双击「启动系统.bat」即可（PHP / MySQL / nginx 全部内置，无需安装任何东西）。

### 重建数据库（清空全部业务数据）

这是唯一的毁灭性操作，所以做了**三重确认**：

1. 批处理里输入 `Y` 继续；
2. **输入管理员密码**（掩码显示，不回显）；
3. **再输一次**，两次必须一致；
4. 再与数据库里 `admin` 账号的真实口令（bcrypt 散列）比对，通过后才真正执行。

任何一步不通过都会**立即取消**，数据库分毫不动。

```powershell
# 正常流程：双击「初始化数据库.bat」按提示操作
# 管理员密码确实丢失时的兜底（谨慎使用）：
powershell -NoProfile -ExecutionPolicy Bypass -File bin\setup.ps1 -Fresh -SkipPasswordCheck
```

口令从**标准输入**传给校验脚本，绝不出现在命令行参数里（命令行参数在任务管理器里是可见的）。
校验脚本是 `database\check_admin_password.php`，加密版里它是加密存放的，照样能用。

## 十二、常见问题

**Q：会不会往系统里装东西？**
不会。所有程序文件都在 `runtime\` 下，不写注册表、不创建 Windows 服务、不装系统服务。删除整个 `E:\PHP_ERP` 目录 = 完全卸载干净（记得先备份 `runtime\data`）。

**Q：端口 3307 / 8090 被占用怎么办？**
MySQL 用 3307 是为了避开本机常见的 3306；Web 用 8090 也是同理。都可以通过上面的命令参数改。

**Q：加密版和源码版能同时跑吗？**
Web 端口都是 8090，**不能同时启动**（启动时会直接提示端口被占用）。
需要同时跑时给其中一套换端口，例如加密版用 `-HttpPort 8091 -DbPort 3308 -CgiBasePort 9020`。
FastCGI 端口段（源码版 9000 起、加密版 9010 起）本来就错开了，不会互相串台。

**Q：安装目录能不能用中文？**
可以。启动脚本会自动在 `%TEMP%` 建一个 ASCII 目录联接，nginx 和 PHP 都走这个别名。
（Windows 的 nginx 不支持中文路径，PHP 的扩展加载也不支持 —— 这两处已经自动处理。）

**Q：能不能放到服务器上跑？**
可以。本机用 root 空密码、局域网用 `erp` / `erp_dev_2024` 账号。正式部署请通过环境变量覆盖数据库配置：`ERP_DB_HOST` `ERP_DB_PORT` `ERP_DB_NAME` `ERP_DB_USER` `ERP_DB_PASS`。

**Q：数据存在哪里？**
`runtime\data\`（MySQL 数据目录）。备份数据库或直接复制该目录即可带走数据。

**Q：第一次运行要多久？**
约 30~60 秒（MySQL 数据目录初始化 + 建表 + 种子数据）。之后每次启动 3~5 秒。
